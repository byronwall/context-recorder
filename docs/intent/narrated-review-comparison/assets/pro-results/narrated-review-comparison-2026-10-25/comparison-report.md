# Context Recorder: adopt, integrate, or keep building?

**Decision:** Keep Context Recorder available for its existing personal, local workflow, but pause broad recorder/editor expansion and make an adopt-first comparison the next investment. **Jam is the strongest general adoption challenger; Clipy and Vidmatic are the closest narrated-batch workflow challengers.** Integrate an existing live-browser inspection and verification path, with a small request/evidence/acceptance record in an ordinary file or existing issue. Continue building only narrow accuracy repairs or a repeatedly demonstrated personal bottleneck. The inspected note-loss defect merits a bounded repair if the tool remains in use; an elaborate new request platform, general video editor, or commercial launch does not yet have an evidence-backed case. This is a research decision and a proposal for later comparison, not a claim that any product completed Byron's work. [J01], [J21], [CL-AREC], [CL-PROOF], [V-ISSUE], [V-WORK], [CR-MD], [CD02]

Research snapshot: **24 October 2026, America/Indianapolis**; retrieval occurred during 25 October UTC. Source baseline: **`1d9f29d4b38c8c964b948b9ba244289947476b9e`**. All external prices are published USD figures, subject to the explicitly recorded plan/billing uncertainty. No product trials or measured comparative results are presented.

## 3. The strongest adoption case

**Jam is the default first challenger because it can replace a large amount of maintained capture and evidence plumbing.** The current product extends well beyond its March MCP announcement: selective timed image/transcript/diagnostic reads, search and mutations, native Mac capture, and agent proof recipes. Its CLI can wrap a check, preserve the exit status and attach browser evidence, provided the check drives the same connected browser. Playwright video/trace imports are documented. A proof loop is therefore already part of the competitive landscape. [J01], [J19], [J21], [J22]

The qualification is substantial: cloud dependence, capture-mode restrictions, data handling and plan limits must fit Byron. Instant Replay is DOM reconstruction and does not expose the same video tools; arbitrary video-frame reads depend on the compatible video backend. A good bug report still does not settle every revision in a long narrated review. These are questions for a bounded comparison, not reasons to dismiss the product. [J01], [J11]

**Clipy is the strongest format-level challenge to custom narrated handoff.** AREC 1.3 is a documented stable, public-domain format with requests, visual evidence, plan, diagnostics boundaries and explicit missing coverage. It can be consumed without a proprietary viewer for the text contract. Its native transcript revision guard, library retrieval and proof ingestion make it more than a generic recording link. Media links, private access and service processing still need attention; a portable Markdown file is not automatically a durable offline evidence archive. [CL-SPEC], [CL-MCP], [CL-SEC]

**Vidmatic is the strongest orchestration-level challenge.** Its default skill produces one issue with multiple ask rows and agent-found source anchors, then tracks stages/requirements and proof links. That directly addresses the desire to avoid writing individual tickets. The agent computes the repository mapping; the server is not independently proving code correctness. A later spoken correction that conflicts with an earlier mark is an especially useful test because its evidence guidance favors marks in conflicts. [V-ISSUE], [V-WORK], [V-INTEL]

These three deserve serious consideration before new infrastructure. **Jam and Clipy are the default two full-trial challengers.** Vidmatic should replace either if the chosen coding client, access prerequisites or preference for its issue/workstream flow makes it the better fit in the predeclared eligibility pass. Loom is a credible alternate if Atlassian adoption is attractive; CaptureCat enters if local processing/control is the decisive constraint. This is a decision about Byron's task, not a market ranking.

## 4. What Context Recorder already has, and the precise gaps

### Existing capability should not be erased by older research

The pinned source contains deliberate display/mic capture, marks/crops, asynchronous browser snapshots, local timed transcription, mark notes and review marks, image/video annotations, nondestructive editing/joins, portable outputs, Product Grid upserts and optional authenticated cloud MCP. Native Find is documented in README; its implementation was outside the selected packet. Canvas is documented and connected through package/module references, but the core analyzer files were not in this packet; no canvas execution was tested. Older research at a different commit is not evidence that these features are missing now. [CR-REC], [CR-REVIEW], [CR-EDITS], [CR-README], [CR-PGM], [CR-MCP]

Browser evidence is useful and bounded. The extension records hovered/focused elements, selectors, regions, framework/source hints, warnings/errors, clicks/navigation and fetch/XHR context. Selectors are checked at capture time, not persistent identities. Region sampling is not a complete DOM tree. MHTML is a saved page, not mutation replay. React props/source metadata do not establish equivalent Solid introspection. Recognized development source attributes are the practical Solid route. Failed response snippets are capped; this is not full HAR/payload or distributed tracing. [CR-PAGE], [CR-BG]

### Source-proven handoff failures and limitations

| Finding at the pinned commit | Consequence and proportionate response |
|---|---|
| Native `MarkText.title/markdown` and Python `mark_markdown` include notes/review origin; cloud `markdown.ts:titleOf/markdownFor` and web equivalents omit them. | A correction written in a mark note can disappear from the agent's usual view. Plan a small parity repair; until then, use canonical JSON plus complete transcript as explicit additional evidence. This is a static source finding, not an executed regression. [CR-TEXT], [CR-PROCESS], [CR-MD], [CR-VIEWER] |

| Cloud input hash identifies changed recording inputs; schemas lack a source-repo/ref/build relationship. | Capture freshness is different from correct source revision. Add a small declared provenance sidecar only when wrong-base work is a real cost. [CR-MANIFEST], [CR-BUNDLE] |

### Missing links: build, integrate, or handle in the agent workflow

The useful chain is **final intended request → original evidence → current source/build/target → changed code → observed acceptance**. It can begin in a Markdown table; it does not require a new service.

| Missing relationship | First response and reason |
|---|---|
| Multiple asks, duplicates, corrections, canceled instructions | Use the chosen product's extraction plus a short reviewer-approved request list. Clipy/Loom/Vidmatic already cover parts. Build only if repeated final-intent loss remains. [CL-AREC], [L01], [V-ISSUE] |
| Evidence versus interpretation | Preserve original quote/time/frame and label inferred code target. Ask when ambiguity affects behavior. A visual target does not necessarily state desired behavior. [CL-SPEC], [TR-LLMS] |
| Repository/ref, running build, dirty state, dependencies | Start with declared commit, app URL/build and lockfile/runtime references. Record unknown relationships honestly; a source hint or custom metadata string is not attestation. [CR-MANIFEST], [CL-BUG] |
| Target survives rerender/current app differs | Reinspect the live app using existing browser tools. Refresh handles and verify the current build; do not recreate a browser automation stack. [CD02] |
| Change and verification evidence | Keep request IDs beside change refs, test command/result and visual acceptance. Reuse Jam/Clipy/Vidmatic proof or ordinary test artifacts; independently review agent-reported success. [J21], [CL-PROOF], [V-WORK] |
| Difficult production/runtime failure | Attach focused Replay, Sentry or OpenReplay evidence when needed. Do not burden every design request with an observability deployment. [RP05], [SE01], [OR03] |

### Privacy must follow each evidence channel

**Local capture, local processing, user-controlled hosting and safe sharing are different properties.** Context Recorder can retain capture/transcription locally, but pushing a cloud bundle exports multiple channels; the chosen coding agent receives what is provided. CaptureCat similarly offers local processing, while custom S3 is only media storage, not full service selfhosting. Its manual blur does not remove originals or track moving content automatically. [CR-CLOUD], [CR-BUNDLE], [C-HOST], [C-STORAGE], [C-BLUR]

Clipy's Mac local mode keeps media on disk but sends transcripts/sample interactions for key moments. Windows audio is server-transcribed. ThinkRun local capture/control can operate without an account, but configured API keys can sync actions to the cloud. Cloud analysis is a separate data flow. Breadcrumb/screenpipe local histories can be disclosed to a cloud model through retrieval. None of these should be compressed into a single “offline” badge. [CL-LOCAL], [TR-CLI], [TR-PRIV], [B04], [SP05]

Hosted products add channel-specific boundaries: Jam distinguishes video blur, SDK sanitizers and recording-link auto-blur; BrowserStack explicitly excludes screenshots/video from metadata redaction; Marker visual masks and payload filtering differ; OpenReplay SDK privacy options cannot be assumed to govern Spot. Clipy full network detail is opt-in and capped, with richer bodies available through diagnostics rather than AREC. Synthetic-secret tests must inspect pixels, speech, transcript, logs, payloads, DOM/MHTML, original assets and exported agent text separately. [J02], [J13], [J14], [B-MASK], [M-MASK], [OR07], [OR08], [CL-BUG]

Retention also differs materially. Jam individual deletion archives by default. Vidmatic human recordings default private, while agent demos default public unless changed; deleted media has a ten-day recovery period. Clipy local recordings can move to Trash after14 days unless kept; hosted video/browser diagnostics follow recording deletion, backups can last30 days, and crash telemetry has a separate90 day rule. Sentry replay retention is30 days free/90paid; OpenReplay Spot links expire after2 days and serverless Spots after30 days. These are distinct service/mode policies, not a single export guarantee. [J11], [V-SHARE], [V-SEC], [CL-LOCAL], [CL-TRUST], [SE04], [OR02]

## 6. What comparison would decide the next investment?

Use the exact pinned Context Recorder web viewer as the real application. The plan requests five useful changes backed by inspected source: **preserve notes through handoff; add web Find; add Copy visible while retaining Copy all; identify review marks; label absent transcripts honestly**. Include a correction, withdrawn instruction, ambiguous copy target and rerender in a twelve-minute walkthrough. These are related viewer tasks, not five statistically independent tests or a production-telemetry benchmark. [CR-VIEWER], [CR-MD], [CR-TEXT], [CR-PROCESS]

Run four clean arms after future authorization: Context Recorder, Jam and Clipy by default (Vidmatic can substitute after a documented eligibility decision), and screenshots plus written instructions. Freeze the same exact agent/model/settings, app/build, fixtures and acceptance criteria. Let products use their native strengths. Give all arms equal external browser/testing tools. Count all authoring, correction, handoff, clarification, request repair, code review, verification and cleanup. A blocked or failed run retains its sunk effort. PR count and recording speed are secondary.

Acceptance requires all five final requests, no canceled behavior, no unresolved wrong target/regression and reviewed evidence from the actual tested build. The proposed adoption margin is **25% and at least ten active human minutes saved** versus Context Recorder, with acceptable privacy and cost. The chosen product must also beat the best acceptable written baseline, or have an explicitly valued control/privacy benefit that justifies extra effort or cost. This is a chosen decision threshold, not an empirical law. First round is capped at six active hours; a tie or material confound permits only a two-hour second batch between the decision-relevant arms. At eight hours, decide provisionally or retain the existing workflow; do not expand into endless product testing. No trial was run.

The six conditional milestones are independently useful: handoff parity; a plain request register if reconciliation fails; explicit provenance if wrong-base work occurs; selective export if sharing is blocked; reused live verification if acceptance is weak; and development-only Solid source hints if source location is costly. Each has exact existing/proposed paths, proof, risk and a next Design-mode question in the plan. **Build is a planning classification, not permission.**

## 7. Personal utility, commercial differentiation, and naming

**Personal:** keeping a tool that fits Byron's habits, preserves local evidence, exposes useful source context and is enjoyable to shape can be rational even if a vendor has more features. The maintenance budget should be justified by actual use or clearly valued control. A replacement need not reproduce canvas, Product Grid or every native interaction to win the main workload; those unique strengths should be measured if they matter. [CR-README], [CR-PGM]

**Commercial:** narration, MCP, request extraction, code anchors, local video, transcript editing, proof recordings and PR links are already documented in competing products. A defensible hypothesis would be reliably preserving final intent through ambiguity, corrections, stale targets and independent acceptance with less work. This research establishes neither demand nor superior outcomes, and documentation gaps do not establish a moat. Defer commercialization until repeated external use supplies evidence; that gate does not invalidate personal improvements. [CL-SPEC], [V-ISSUE], [V-WORK], [J21], [C-MCP]

**Naming:** avoid **Breadcrumbs** as the public product name. Innerloop **Breadcrumb** already targets developer/coding-agent context and memory; pluralization and domains such as dropbreadcrumbs.dev, mybreadcrumbs.dev or sendbreadcrumbs.com do not remove the adjacent audience/purpose confusion. This independently supports the prior naming hypothesis while remaining separate from usefulness. No trademark clearance, domain availability determination, purchase or rename was performed. A personal internal nickname is a different decision. [B01], [B02], [B03]
